# Bundled icon theme (full Adwaita SVG set)

`icons.gresource` (compiled from `icons.gresource.xml`) embeds the complete
Adwaita SVG icon set — every symbolic and scalable fullcolour icon — as
**flat SVG files at the resource root** (`/picrs/icons/<name>.svg`), 715
icons as of the 49.x theme.

## Why flat?

GTK 4.22's `gtk_icon_theme_add_resource_path()` enumerates only the direct
children of the registered path and registers them as unthemed fallback
icons (extension stripped, SVG preferred). Subdirectory layouts such as
`hicolor/symbolic/actions/...` or `scalable/actions/...` are silently
ignored there, despite what the doc comment implies. GTK's own built-in
fallback icons (`/org/gtk/libgtk/icons/`) use the same flat layout.

Linux resolves these names from the system Adwaita theme first; the bundle
is what makes icons render on Windows/macOS, which ship no system icon
theme at all. With the full set bundled, every icon the app references —
and anything added later — resolves on every platform.

## Regenerating

Run from the repository root on a machine that has `adwaita-icon-theme` installed (Linux package,
or `brew install adwaita-icon-theme` on macOS):

    ./scripts/build-icon-bundle.sh                       # /usr/share/icons/Adwaita
    ./scripts/build-icon-bundle.sh /path/to/Adwaita      # custom source

The script imports all SVGs into `resources/icons/` (deduplicating by basename),
recreates the `view-sidebar-symbolic.svg` stand-in (missing upstream), and
regenerates both `resources/icons.gresource.xml` and the compiled `resources/icons.gresource`.
The XML and SVGs are checked in, so a plain rebuild needs nothing extra:

    glib-compile-resources --sourcedir=resources --target=resources/icons.gresource \
        resources/icons.gresource.xml

Ordinary `cargo build` does not even need that: `src/main.rs` embeds the
prebuilt `icons.gresource` via `include_bytes!`, so icons ship in every
release binary automatically.

## Auditing app references

Check the icon names used in `src/main.rs` against `resources/icons/`.
The prebuilt bundle is embedded with `include_bytes!` and registered when
the application starts.

## Icon sources / licensing

Icons come from adwaita-icon-theme (LGPL-3.0-or-later OR CC-BY-SA-3.0).
Two stand-ins bridge names upstream does not ship (both regenerated by the
script): `view-sidebar-symbolic.svg` copies `sidebar-show-symbolic.svg`, and
`sidebar-hide-symbolic.svg` mirrors it horizontally.

## Application package icons

The PNG application icons used by the Linux packagers are in `icon/`,
with filenames such as `pic-48.png`. They are separate from the embedded
SVG theme in `resources/icons/`. To regenerate the application sizes from
original artwork, run `./scripts/generate-icon.sh /path/to/original.png`
from the repository root. This overwrites the generated sizes in `icon/`.
