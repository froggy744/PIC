# PIC Glossary

Domain terms used in code, docs and reviews. Use these names exactly; code paths are in `AUDIT-INDEX.md`.

| Term | Meaning |
|---|---|
| **Gallery surface** | One of the widgets that shows photo tiles: the All Photos `GtkGridView`, the sectioned Folder view (`gtk::Fixed`, also used by every wall layout), or the legacy Folder list. Only one is on screen at a time. |
| **Gallery scroller** | The scrolled window a per-frame thumbnail pump belongs to: `Photos` (All Photos) or `Folder`. A pump acts only while its own surface is on screen. Code: `GalleryScroller`. |
| **Thumbnail presentation** | Getting the right thumbnail, at the right size, onto every visible tile: visibility, request queueing, prefetch, the decoded-thumbnail RAM cache and delivery. One module: `grid/presentation.rs`. |
| **Visible tiles** | A surface's visible band plus where each tile is *placed* (not where GTK last allocated it). The seam every surface answers through. Code: `visible_presentation_tiles`. |
| **Presentation target** | The short-edge size, in device pixels, a gallery thumbnail is decoded at for the current zoom (128/192/256/384 px buckets, or full size). Cached thumbnails remember the target they were decoded for. |
| **Stand-in** | A cached thumbnail decoded for a smaller zoom, shown while the sharper one loads, so a zoom-in never blanks a tile. |
| **Settled tile** | A tile showing its thumbnail at a size good enough for the current presentation target. Pumps skip settled tiles. |
| **Scrub** | A direct scrollbar drag that moves more than about a page per event; it switches the pumps to model-derived targets. Decided by `ScrollMotion::moved` (`window/scroll_motion.rs`). |
| **Settle** | The moment scrolling stops (90 ms of quiet after a scrub in All Photos, 110 ms after any move in Folders), when visible tiles are refreshed and prefetch runs within the RAM cache budget. Only the newest `SettleTicket` settles. |
| **Gallery scroll motion** | What a gallery does while its scroller moves: scrub, target sampling, settle and the per-frame thumbnail pump. One module, `window/scroll_motion.rs`, with one `ScrollMotionSpec` per gallery (`ALL_PHOTOS`, `FOLDERS`). The wheel glide (`WheelGlide`) is separate. |
| **Screensaver style spec** | Everything PIC knows about one screensaver style, in one row: saved key, label, subtitle, stage, default tiles, background, photo and Terminal-only flags. Code: `Style::spec` (`screensaver/style.rs`). |
| **Screensaver stage** | The renderer family a style plays on (`Wall`, `Prints`, `Flying`, `CoverFlow`, `Cinema`); it sets the Settings tile limit, the player's slots and the decode size. Code: `Stage`. |
| **Recipe** | `EditRecipe`: the non-destructive edit description applied at display and export time. Originals are never modified. |
| **Sidebar mode** | Which left navigation the user chose: the **full sidebar** inside the split view, or the **compact rail**. Persisted as `compact-sidebar-enabled`. Code: `SidebarMode`. |
| **Compact rail** | The narrow icon navigation (44-300 px) beside the split view, in its own dock. Labels appear from 90 px. |
| **Drawer** | The full sidebar while the split is collapsed by the responsive breakpoint (window ≤ 1050 px, back at ≥ 1080 px): it slides over the photos instead of sitting beside them. |
| **Hover peek** | Opening the hidden full sidebar by resting the pointer on the left-edge strip. It does not change the pin, and closes again when the pointer leaves. |
| **Immersive overlay** | In Immersive Mode, the existing sidebar shell moved onto the gallery as a presentation-only overlay, showing the full or compact page per the sidebar mode, so the gallery never reflows. |
| **Sidebar presentation** | Deciding how the left navigation is shown for a sidebar mode, breakpoint, pin/hover and Immersive Mode: which widgets are visible, where, and how wide. One module: `window/sidebar_presentation.rs`. |
| **InfoBar presentation** | Deciding what the bottom InfoBar shows: nothing, one photo's metadata, or the **selection strip** (count, thumbnails and grouped actions for a multi-selection), and which of its buttons are enabled. Callers report events; the lightbox and the date overview **cover** the gallery, so gallery events wait until they close. One module: `infobar_presentation.rs` (`infobar::presentation`), applied by `InfoBar`. |
| **Properties inspector** | The photo details panel: the **gallery panel** docked beside the photos, or the **viewer panel** over the lightbox. Each has its own open state and scroll position. |
| **Current photo** | The one photo the photo actions (marks, rotate, edit, export, print, albums, Properties toggle, Space, digit keys) anchor on. It is the photo the InfoBar shows, decided by **InfoBar presentation** (lightbox photo while the viewer is open, else the gallery focus; the date browser's first selected photo; cleared by an empty selection, the date overview, trash or a library switch). Read it with `InfoBar::current_photo`; nothing else keeps a copy. |
| **Front surface** | The surface the user is looking at, which decides where input goes (zoom slider, 1:1, keys, Escape, collection navigation, mark targets): `Lightbox`, `Editor`, `Collage`, `DateOverview`, `Gallery`, `LibraryHome`, `Albums`, `FoldersOverview`. One precedence, page first: Editor, Collage, Albums and Folders overview win by page; the viewer counts only over Photos or Library; then the date overview, then the gallery (the date browser's day view is the gallery). Read it with `FrontSurface::current()`; it is computed from the live widgets and never cached. Two related questions: `gallery_covered()` (the viewer or date overview hides the gallery, whatever the page) and `date_browser()` (the date browser's level). Pure precedence and reader: `window/front_surface.rs`. |
| **Front change** | A change of the front surface's inputs (page, viewer shown, date browser level), delivered by `FrontSurface::connect_changed` as before/after `FrontState`s: synchronously, in registration order, before any other viewer or page handler. A change made during a delivery is delivered at once and supersedes it (GTK itself queues a page change made inside a page notification). **Front mirrors** (`window/front_mirrors.rs`) is the listener that keeps the InfoBar, Properties and the metadata panel in step. |
| **Zoom slider** | The InfoBar's one shared zoom slider, in one of three modes picked from the **front surface**: Thumbnails (gallery thumbnail size, one stop per zoom level), Photo (viewer zoom) or Edit (editor zoom), the last two running Fit (left), 100% (middle), 200% (right). What it shows is decided in `window/zoom_slider.rs` (modes, specs, conversions, wheel step; pure) and written only by `ZoomSliderWidgets` (`window/zoom_slider_widgets.rs`), a **front change** listener; a surface's zoom report applies only in its own mode. |
| **Window session** | What the window remembers per library between runs: the last view, the gallery or albums scroll and the anchor photo, the last activated photo, the window size and the split widths. Loaded once as `SessionState` and saved through `record` in `window/session_state.rs`; leaving a library (close, or before a library switch) saves one **leave snapshot**. |
| **Browse scope** | What the user is browsing, as one value: the destination (All Photos, a folder, Favourites, an album, History, Ratings, Rating(n), the Albums home), the search, the toolbar rating and the saved metadata filters. Every browsing query, facet count and album count takes one; it decides the **effective rating** (a sidebar Ratings destination replaces the toolbar's), whether the view is narrowed, and the SQL membership. Workers take a snapshot (`BrowseSnapshot`) and drop results once the scope or library changed. Code: `db::BrowseScope` (`src/db/browse_scope.rs`); the sidebar mapping is `browse_scope` in `window/library.rs`. |
| **Smart Album** | An album whose photos are chosen by saved rules (`filters::AlbumRules` in `albums.rules`) instead of manual membership. A read-only photo source: never an Add to Album destination. Membership is the one predicate `db::album_membership`; manual albums are those with no rules. |
| **Photo marks** | A photo's favourite flag and 0-5 star rating. Changed only through **photo mark commands**: a control reports an intent (toggle favourite, toggle stars, set rating) for its **anchor** photo, and the plan picks the targets (the lightbox photo, or the gallery selection, or the collage ticks), the value, and whether photos leave the view. Pure plan: `window/photo_marks.rs`; adapter: `window/photo_mark_commands.rs`. |
| **Properties presentation** | Deciding when each Properties panel is shown: the Photos-page gate, the viewer, and Immersive Mode, which **suspends** the panels (hidden, not closed; they resume afterwards). One module: `window/properties_presentation.rs`. |
