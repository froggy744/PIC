Architecture review: round four

Rounds one to three (1-20) are all merged or closed. This round covers what is still inline in build() and, for the first time, the editor and lightbox.

module seam leakage / divergent copy deep module

Context finding

layout.rs, toolbar.rs, immersive.rs and shortcuts.rs are include!d into the body of build() (build.rs:229, 4669, 4884, 4952). The real build() is about 9,000 lines in one shared scope, with 59 *_slot cells and about 121 Rc<Cell/RefCell> cells. Turning the include!s into modules on its own is rejected because complexity would only move. The candidates below name concepts that deserve a seam even if the files stay as they are.

Problem: the edit and collage session is a state machine spread over 2 flags (9 writers in 2 files), 6 slot clears and 3 handlers that each work it out again. The editor's own close has 4 return routes and the InfoBar Edit toggle has 2.

Solution: one pure session value decides the return route and teardown for every way out. The GTK adapter applies the result.
